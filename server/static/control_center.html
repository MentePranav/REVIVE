Zero-Trust Policy & Safety Rule Governance

Strict deterministic rule hierarchy enforced before any execution authorization
P001

Input & Schema Validation

Verifies transaction amount > 0, currency format, and observable metadata integrity. Fails closed on malformed input.

FAIL CLOSED
P002

Payment State Resolution Check

Blocks execution if payment is already CAPTURED, SUCCESS, or settled out-of-band to prevent double-recovery charges.

DOUBLE-RECOVERY GUARD
P003

Automated Attempt Cap Safety (Hard Limit: 2 attempts)

Strictly prohibits a 3rd automated recovery attempt on any payment ID to prevent infinite retry loops and fee waste.

ATTEMPT CAP
P004

Diagnostic Confidence Gate (Threshold: >= 0.85)

If root-cause diagnostic certainty < 85%, automated execution is blocked and escalated to Human Review queue.

CONFIDENCE GATE
P005

High-Risk Fraud & Chargeback Gate

Blocks automated interventions on accounts flagged with stolen card or suspicious velocity and routes to Risk Review.

RISK GATE
P006

Action Allowlist Check

Ensures only registered, permitted recovery verbs (RETRY, REMINDER, PAYMENT_LINK, HUMAN_REVIEW, DO_NOTHING) can be processed.

ALLOWLIST
P007

Customer Contact Fatigue Limits (Max 2 contacts)

Limits reminders and payment links to prevent customer communication spam and preserve merchant reputation.

FATIGUE GUARD
P008

Mandatory 300-Second Cooldown Interval

Enforces a 5-minute pause between repeated actions on the same transaction to respect bank clearing queues.

COOLDOWN GUARD
P009

Communication Template Allowlist

Permits only registered, pre-approved notification templates to prevent phishing or script injection.

TEMPLATE GUARD
P010

Validated ExecutionAuthorization Token Issuance

Instantiates an immutable authorization token strictly when all deterministic safety gates pass.

⚖️ Primary Architectural Tradeoff
"REVIVE recovered 75.19% of RULE_BASED gross revenue while using 22.37% fewer interventions."
REVIVE deliberately trades some gross recovery for fewer interventions and explicit safety governance. Unconstrained RULE_BASED heuristics achieve higher gross recovery through aggressive, repetitive retry attempts without attempt limits, cooldowns, or fraud risk checks. REVIVE enforces hard 2-attempt limits (P003), customer communication fatigue limits (P007), 300s cooldowns (P008), diagnostic confidence boundaries (P004), and blocks all automated actions on high-risk accounts (P005).
