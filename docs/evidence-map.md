# REVIVE — Buildathon Track 3 Evidence & Requirement Map

This document establishes the empirical mapping between Track 3 (AI Revenue Recovery) requirements and the REVIVE implementation.

---

## Comprehensive Requirement-to-Evidence Matrix

| # | Requirement / Claim | REVIVE Implementation | Evidence / Artifact | How Evaluator Can Verify | Limitations & Boundary |
| :- | :--- | :--- | :--- | :--- | :--- |
| **1** | **Failed Transaction Ingestion** | Ingests failed transactions and abandoned checkouts with error codes and customer metadata. | `simulator/public_schema.py`<br>`agent/features.py` | Run `pytest tests/test_simulator.py`<br>Inspect Recovery Cases tab in Web UI. | Operates on simulated/synthetic schema; no live Razorpay webhook ingress. |

| **10** | **Automated Stopping Rules** | Enforces hard cap of 2 automated recovery attempts per transaction to prevent infinite retry loops. | `policy/engine.py` (Rule P003)<br>`tests/test_policy.py` | Run `pytest tests/test_policy.py -k test_5`<br>Test adversarial 3rd attempt rejection. | Hardcoded threshold of 2 attempts. |
| **11** | **Customer Contact Limits** | Limits customer reminders and payment links to maximum 2 contacts per customer to prevent communication spam. | `policy/engine.py` (Rule P007)<br>`policy/state_context.py` | Run `pytest tests/test_policy.py -k test_8`<br>Inspect safety summary in UI. | In-memory customer state tracking. |
| **12** | **Payment-State Verification** | Checks live payment status before execution; blocks actions on already resolved or captured payments. | `policy/engine.py` (Rule P002)<br>`execution/executor.py` | Run `pytest tests/test_adversarial_hardening.py -k test_adv_4`. | Validates simulated payment context state. |
| **13** | **Idempotency & Duplicate Guards** | SHA-256 idempotency key prevents duplicate execution even under rapid double-clicking. | `execution/executor.py`<br>`server/static/app.js` | Double click "Execute Simulated Recovery" in Web UI; check duplicate audit log. | Key cached in-memory per session. |
| **14** | **Immutable Audit Trail** | Logs every decision, authorization, execution, and outcome with timestamps and trace IDs. | `execution/models.py`<br>`server/app.py` | Navigate to "Audit Log" tab in Web UI; view raw JSON event payloads. | Audit log resides in memory and report files; no external cold storage. |
| **15** | **Deterministic Reproducibility** | Fixed random seeds and SHA-256 configuration fingerprint yield identical results across repeated runs. | `core/config.py`<br>`evaluation/experiment/` | Check `GET /api/health`<br>Run simulation on Seed 42 twice; observe identical numbers. | Relies on standard pseudo-random number generator seeds. |
| **16** | **Fail-Closed Behavior** | Missing authorization, invalid schema, negative amounts, or unknown actions immediately fail closed. | `core/errors.py`<br>`execution/executor.py` | Run `pytest tests/test_adversarial_hardening.py` (20 edge cases). | Rejects execution silently or with structured 400/403/404 JSON. |
| **17** | **Zero-Trust Policy Enforcement** | Execution layer strictly refuses to run without a valid, validated `ExecutionAuthorization` issued only after policy gates pass. | `policy/models.py`<br>`execution/executor.py` | Run `pytest tests/test_execution.py -k test_5`. | Architecture separation enforced locally. |
| **18** | **Explainability & Attribution** | Explains why an action was chosen, displaying top positive/negative feature attributions. | `agent/scoring.py`<br>`server/models.py` | Open any case modal in UI; view "Top Explainability Factors". | Linear feature contribution breakdown. |
| **19** | **Synthetic Methodology** | Controlled holdout evaluation using independent seeds and isolated ground truth counterfactuals. | `simulator/`<br>`evaluation/experiment/` | Read `docs/architecture.md`<br>Run `pytest tests/test_simulator.py`. | Ground truth is statistically modeled, not scraped from real cardholders. |
| **20** | **Known Limitations** | Complete transparency regarding simulation scope, absence of live bank rails, and lack of real merchant A/B tests. | `docs/failure-analysis.md`<br>`README.md` | Read Failure Analysis & README. | Explicitly documented; no production deployment claims made. |
